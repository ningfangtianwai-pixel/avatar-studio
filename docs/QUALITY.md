# 配音、字幕与音画质量检查

## 为什么需要这次修复

v0.2.1 存在严重的质量放行缺陷：短文案可能生成到长度预算上限，包含长时间异常声音，却仍被送入口型渲染；Markdown 标记进入朗读和字幕；字幕按整段文本长度估时。短冒烟、文件可播放、固定帧率都没有覆盖这些内容质量失败。

v0.3.0 将检查前移到昂贵的口型渲染之前。它不是重新训练模型，也不保证所有声音、人像和语言均达到相同质量。

当前生成和识别均按中文运行。方言、声调差异、英文长段及大量中英混读不在充分验证范围内；不要把这些中文阈值当作通用语音标准。

## 现在的流程

文案格式清洗 → 语义分段 → 配音 → 每段声学与转写检查 → 有限重试/缩短分段 → 语音时间锚点字幕 → 整数帧章节 → 口型 → 逐章帧数核验 → 合成与完整解码 → 可选同步评分 → 预览验收。

- 文案：清除强调、标题、链接等常见 Markdown 标记；保留原始任务文案，显示与朗读使用清洗文本。不是完整 Markdown/HTML 渲染器。
- 分段：默认目标 60、上限 88 字符，失败最多重试一次；仍失败时只允许再拆分一级，每个子段最多两次。达到限制后失败，不无限消耗 GPU。
- 声学检查：非有限值、长度离群、生成码接近预算上限、长低能量间隔、有效声音比例。不会把缩小生成上限后的截断音频当成成功。
- 繁简体/同音转写：整体读音完全一致时，不因字符误差高而拒绝；相同读音也可提供字幕时间锚点。这不是任意文本纠错，实际发音偏离仍按局部规则检查。
- 内容检查：逐段离线 Whisper 转写，与文案比较；除整段误差外，还检查连续词组的局部偏离，避免一句读错被整段平均值掩盖。连续两个及以上被替换的字符若拼音不一致，也会拒绝，不只检查长句偏离。用 pypinyin 比较不含声调的拼音以容忍部分同音字误识别；拒绝较大偏离、长缺失/重复和疑似额外尾词。ASR 和多音字转换会误识别，因此可能误拒绝，也可能漏检；不能取代听辨。单字、声调、口音等细节仍需人工检查。
- 字幕：按识别字符的实际时间锚点定位，少量未匹配字符在邻近锚点间插值；特殊分词无法还原时退回该识别短句内部插值。**这是 ASR 辅助近似对齐，尚未实现逐字强制对齐或音素级强制对齐。** 不再将整个 TTS 长段按文案长度均摊。词组换行优先标点，避免将“了”等助词推至行首；句末引号归回前句，不跨句末强行合并。排版仍为启发式，不保证任何文本都具有最佳断句。
- 时间轴：24 kHz 音频的 960 个样本对应一帧；章节共享整数帧起点，严格限制长度，尾部最多补不到一帧静音。MuseTalk 的帧计数补丁避免浮点向下取整偶尔少一帧。
- 成片：逐章核对帧率/帧数/音轨长度，最终完整解码；不再靠长尾定格掩盖未知时长缺口。文件完成后仍提示预览验收。

## 必须配置：离线 Whisper

使用 [whisper.cpp](https://github.com/ggml-org/whisper.cpp) 的 `whisper-cli` 和兼容中文的 `ggml-small.bin`（或已验证兼容的模型）。可复用现有本地安装，不需要云端 API。不将媒体上传到第三方。

在忽略的 `studio.local.json` 设置：

```json
{
  "AVATAR_STUDIO_WHISPER_BIN": "/path/to/whisper-cli",
  "AVATAR_STUDIO_WHISPER_MODEL": "/path/to/ggml-small.bin"
}
```

相同名称的环境变量优先。默认二进制路径为 `AI_PROJECT/tools/whisper.cpp/build/bin/whisper-cli`，模型默认 `AI_PROJECT/models/whisper/ggml-small.bin`。缺失时直接报错，不静默跳过。模型环境需已有 numpy、soundfile、jieba；在现有 TTS 环境追加小型质量检查依赖，不升级 torch，也不应将 TTS 和 MuseTalk 合并到同一环境：

```bash
uv pip install --python /path/to/tts-python --no-deps -r pipeline/requirements-quality.txt
```

当前固定 `pypinyin==0.55.0`，用于中文发音近似比对，不用于生成语音或声调识别。

## MuseTalk 补丁升级

`patches/musetalk-phase.patch` 是对 README 中固定上游提交的**完整累计补丁**，包含原动作相位处理以及新坐标检查和整数帧计数。不能在已应用旧补丁的目录上直接再次应用完整补丁。

升级前备份并查看 `git diff`。仅当旧补丁没有与自己的修改重叠时，用 v0.2.1 的原补丁先做 `git apply --reverse --check`，再反向应用；之后对新补丁 `git apply --check` 并应用。检查失败就停止并手工合并，禁止强制覆盖或重置工作区。新坐标 JSON 供同步评分使用；缺失/无效人脸框直接拒绝渲染，避免帧、坐标和潜变量错配。

## 可选：独立嘴型同步评估

支持 [Joon Son Chung 的 SyncNet](https://github.com/joonson/syncnet_python)，外部源码和模型不打包进本项目。已验证上游提交 `907c0b579c2e2d83f0eae1b2ac9e720cde4e5623`，官方 `syncnet_v2.model` SHA-256：

```text
961e8696f888fce4f3f3a6c3d5b3267cf5b343100b238e79b2659bff2c605442
```

使用官方仓库 `download_model.sh` 所列 Oxford 来源的 HTTPS 地址下载评分模型。本集成复用渲染器人脸框，不要求下载另一个人脸检测模型。为避免修改既有模型环境，可将小依赖单独安装到工具目录：

```bash
uv pip install --target /path/to/syncnet_python/.deps --no-deps python_speech_features==0.6
```

配置 `AVATAR_STUDIO_SYNCNET_DIR` 指向该源码目录；默认 `AI_PROJECT/tools/syncnet_python`。当其 `data/syncnet_v2.model` 存在时，最终合成会自动运行评分。配置不完整、评分进程失败、有效窗口偏移超过 3 帧或置信度低于 2 时，停止发布并保留任务产物供复核；这些是本工作台的保守启发式阈值，**不是论文给出的通用合格标准**。未安装评分模型时仍可生成，报告会明确要求人工口型复核。

评分工具先用官方示例校验：本机测得偏移 3 帧、置信度约 10.08，与官方示例近似。工作台每 10 秒计算一个窗口；过短尾窗不足以评分。评分沿用参考人脸框裁剪，而非对生成脸独立追踪，无法检测所有脸部抖动、假牙形态、动作不自然或说错字。

参考视频仍会往返循环；相位延续不等于生成新动作。不得宣传消除全部卡顿、达到完全真人口型或保证任何长片无故障。

## 报告与验收

- `narration/quality.json`：每次尝试的声学指标、识别结果、拒绝原因与最终状态。
- `narration/segments/candidate-*.asr.json`：逐段原始识别结果。
- `narration/timeline.json`：精确采样位置及 ASR 时间锚点。
- `lipsync-quality.json`：已配置 SyncNet 时的分窗估计。
- `quality.json`：技术检查总结；不是主观质量保证。

上述文件都在私有 runtime 内，可能包含人像、声音、文案、识别文本和本机路径，**不要上传到公开仓库或 Issue**。反馈时只提供脱敏、必要的指标。

修复验收须覆盖：无格式残留、无异常超长/低能量段、文案无明显多读漏读、字幕与朗读对应、头中尾及章节接缝口型、完整解码、素材/数据库保留。先短样，后长片；检查不通过，不发布修复版。

```bash
/path/to/tts-python -m unittest discover -s tests -p test_quality.py -v
npm run lint
npm run build
```
