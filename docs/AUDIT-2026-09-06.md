# 数字人工作台审计 · 2026-09-06

作者：Manny

审计范围：工作台前端、FastAPI/SQLite、素材管理、任务编排、源码发布边界。不是第三方模型安全认证或法律意见。

## 结论

具有开源价值，建议定位为本地单用户、单 GPU 的创作者工作台，以实验版发布。价值主要在素材管理、队列、语音/口型/字幕的整合，而不是自研模型。当前尚不适合多用户、公网或无人值守商业托管。

原创代码可按 MIT 发布并保留 Manny；第三方依赖、模型、媒体授权仍分别适用原许可。源码发布不包含私人素材，不代表任何输入或输出自动取得商业使用权。

## 已修复的问题

| 优先级 | 问题 | 修复 |
| --- | --- | --- |
| 高 | 重试重新生成语音却可能复用旧口型章节 | 每次尝试创建独立目录，禁止跨尝试复用旧章节；代价是重试重新计算 |
| 高 | 多后端实例可能重置运行状态并争抢 GPU | 初始化恢复前取得进程级文件锁；第二实例拒绝启动 |
| 高 | 仅 CORS 不足以阻止普通跨站表单写入本地接口 | 回环监听、Host/Origin 校验、写操作要求自定义请求头；仍不等于身份认证 |
| 高 | 上传体积及媒体规格缺少边界 | 请求/文件体积限制、ffprobe 媒体验证、视频时长/像素及音频时长限制、失败清理 |
| 高（发布阻断） | 个人路径硬编码、个人素材自动导入 | 路径移入忽略的本地配置，删除自动导入逻辑，发布只收集白名单源码 |
| 中 | 活动任务素材可能在生成时被修改 | 事务内检查引用，拒绝活跃素材转码/删除；校验重试引用 |
| 中 | 子进程卡死和停止后残留 | 阶段超时、停止事件、终止进程组；队列异常记录与重试、健康接口检查线程存活 |
| 中 | 成片复制途中可出现半文件 | 先写临时文件，验证后原子替换正式输出 |
| 中 | 重试/取消失败前端无清晰反馈 | 增加错误提示与提交中状态，解析后端表单错误 |
| 中 | 依赖存在已知安全公告 | 更新 React/Vinext/Vite/Cloudflare 相关依赖及 FastAPI/Starlette/multipart，锁定版本 |
| 中 | 日志读取可随日志增长占用大量内存 | 校验任务存在，仅返回最新尝试日志末尾 30 KB |

另增加：10,000 字符文案上限、32 个活动任务上限、磁盘余量预检查、SQLite WAL 与连接释放。现有个人媒体与记录未做脱敏覆盖或删除。

## 保留的问题与建议顺序

1. **逐句/逐字字幕对齐**：当前段内仍按文本长度估时。建议加入本地 forced alignment 后端，并对数字、英文缩写、长停顿做回归；这是下一步最直接的成片质量提升。
2. **情绪配音**：尚无专用情绪控制。应先做短段试听、情绪参考音频和音色稳定性评测，再决定是否切换支持指令的模型。
3. **取消运行与恢复**：目前只支持取消排队，运行中需停服务；缓存没有基于内容指纹的安全断点复用。
4. **长期存储管理**：旧 attempt、回收站与模型缓存不会自动回收；成片只展示最近 100 条，无分页。
5. **任务可观测性**：线程存活不代表 GPU 或数据库一定健康；磁盘剩余检查也不是配额预留。还需要更完整的阶段心跳、告警与磁盘管理。
6. **发布成熟度**：仅本地回环单用户；前端仍使用开发服务器，模型安装没有完全自动化，旧模型依赖需要单独维护。不能通过改监听地址直接变成 SaaS。
7. **删除恢复**：数据库软删除与文件移动不是跨存储原子事务；极端权限/磁盘故障仍可能需要手动修复记录与回收站。
