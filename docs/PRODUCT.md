# 数字人口播工作台 · Avatar Studio

把形象、声音、文案和视频生成放进一个本地工作台。

## 项目介绍

数字人口播工作台面向希望使用自有或已获授权形象、声音制作口播内容的个人创作者。它将原本分散的素材整理、声音格式转换、语音合成、口型驱动、字幕排版和成片管理串联起来。

完成模型环境配置后，你可以在网页中管理数字人形象和声音，输入文案、提交生成任务，并查看进度、错误与成片。日常提交任务不需要再次让编程助手执行命令；推理仍会消耗本机 GPU、电力和存储空间。

系统使用 React / Vinext 前端、FastAPI / SQLite 后端，以及 Qwen3-TTS、MuseTalk 和 FFmpeg。它是对现有开源能力的整合与工作流改进，不是一个新训练的基础模型，也不是通用舞蹈或全身动作复刻系统。

## 相比早期工作流，真实做了哪些优化？

这里的“早期版本”是本工作台原先的拼接式流水线，**不是上游模型的官方基准版本**。这些改变主要发生在文本分段、音频处理、视频编排和任务管理层，没有重新训练模型。

| 方向 | 早期问题 | 当前已经实现 | 仍需注意 |
| --- | --- | --- | --- |
| 配音流畅度 | 文案切得过碎，频繁重新起句，段间断裂明显 | 按句子标点和长度合并短段；目标约 82 字符、上限 110，给 TTS 更多上下文 | 更长的上下文不保证每次语气自然；合段有时会跨原段落 |
| 停顿与音量 | 段间静音堆叠，声音忽大忽小，拼接边缘生硬 | 裁剪首尾多余静音并留边；按标点插入约 0.12–0.24 秒停顿；限制幅度的段间 RMS 调整、10 ms 边缘淡入淡出，最终做响度处理 | 不是语义情绪识别或专业混音；参考录音仍决定很多效果 |
| 视频连贯性 | 独立章节从同一参考动作开头重启，往返循环端点容易重复 | 章节累计帧偏移延续参考动作相位；对通常长度的参考序列，往返循环去掉重复端点 | 仍是参考动作循环；不生成新肢体动作，极短序列采用兼容回退 |
| 音画合成 | 分章音轨与时间戳处理容易累积不连续 | 完整配音只作为一条主音轨进入最终合成；视频章节重置时间戳后拼接，统一为 25 fps | 固定帧率不是补帧，不能消除模型抖动或所有视觉卡顿 |
| 字幕阅读 | 中文词组、数字单位或英文缩写容易拆散 | 基于词组与显示宽度分行，保护数字单位和英文术语，统一最终字幕样式 | 时间仍按语音段内文本长度估算，尚未实现逐字强制对齐 |
| 格式适配 | 输入声音、视频格式不一致导致失败或额外手动处理 | 声音自动转为 24 kHz 单声道 WAV；视频规范为 25 fps，并限制在 720×1280 边界内 | 不会将低清素材变成真正高清素材 |
| 可靠性 | 重试可能混用新配音和旧口型；重复后端可能争抢 GPU | 独立尝试目录、单实例锁、串行队列、超时清理、上传限制、错误提示与成片原子替换 | 不支持安全断点续算，也不是面向公网的多用户系统 |

代码依据：`pipeline/generate_voice.py`、`pipeline/prepare_chapters.py`、`backend/pipeline.py`、`backend/app.py` 和 `patches/musetalk-phase.patch`。

## 验证到了什么程度？

历史本机长片记录中，同一文案的配音段数从 81 段降为 21 段，流程额外插入的停顿总量由 37.26 秒降为 3.72 秒。2026-09-06 已重新核对两次文案文件字节一致及各自时间线统计。这里的“插入停顿”不包含模型自身生成的所有停顿。优化后的约 326.5 秒成片通过了 25 fps 固定帧率与完整解码检查。

这些是既有单机、单样例记录，**不是多样本受控对照实验，也不能解读为流畅度提高了某个百分比**。本次公开包不包含私人对照音视频，因此不能仅凭源码包独立复核历史主观听感。后续欢迎使用已获授权的公开测试素材补充可复现评测。

2026-09-06 工作台审计还完成了 15 项后端与源码发布回归，以及一条 3.10 秒真实 GPU 口播验证。详见 [审计报告](AUDIT-2026-09-06.md)。开源去品牌版本另外进行构建、类型检查、源码品牌扫描与打包检查，不冒称重新完成了长片听感测试。

## 当前边界与下一步

当前面向单机、单用户、单 GPU，主要在 Ubuntu / WSL2 + NVIDIA 环境验证。模型需要自行安装，首次获取权重可能联网；没有一键跨平台安装保证。

计划继续改进逐字字幕对齐、情绪化配音、运行中取消、缓存清理及更完整的性能评测。这些是后续方向，**不是现有功能承诺**。请不要将默认服务暴露到公网。
