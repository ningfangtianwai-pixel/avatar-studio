# Avatar Studio v0.3.0 · 配音质量与时间轴修复预览版

本数字人系统由 **Manny 与 Codex 协作完成**；作者与维护者为 Manny，原创工作台代码采用 MIT。底层模型、工具及媒体仍遵守各自许可。本项目不是 OpenAI 官方产品。

## 修复了什么

v0.2.1 缺少配音内容检查，曾将两段异常超长音频当成功并继续渲染。文件可以解码、固定 25 fps，都不能证明声音、字幕和口型质量正常。这是旧工作流的实际缺陷，不应继续宣传已经全面解决长片质量。

v0.3.0 增加以下工作流改进，没有重新训练 Qwen3-TTS 或 MuseTalk：

- 配音前清理 Markdown，使用较短的语义段与有限生成预算。
- 每段检查时长、生成码数、异常低能量间隔和离线转写；同时比较局部词组发音，避免整体平均误差掩盖局部读偏。
- 失败有限重试，必要时缩短分段；仍不通过就停止口型渲染。相同读音的繁简体/同音字转写不会仅因字形差异被拒绝。
- 字幕使用 ASR 时间锚点；改善句末引号归属与助词换行。仍是近似对齐，不是逐字或音素强制对齐。
- 章节共享整数帧时间轴；逐章核验帧数和音轨长度，最终完整解码，不再用长尾定格遮盖时长缺口。
- 可选本地 SyncNet 分窗评分；配置后自动检查，未配置则明确要求人工口型复核。
- 页面显示配音通过段数/重试次数，失败原因可见；完成提示改为“已生成，请预览验收”。

## 本次实际验证（2026-09-07）

使用已授权的私有中文口播素材，在 Ubuntu 24.04 / WSL2、RTX 2060 12 GB 上完成回归。媒体和原始日志不公开；下面是脱敏指标，不代表所有素材或机器的表现。

- 先验证约 11 秒短样，再跑完整文案。期间两轮候选因复核发现词句疑点未放行，补充回归后重新运行。
- 最终 249 秒、720×1280、25 fps、6,225 帧、3 章；完整解码通过，每帧间隔 40 ms，相邻完全相同帧为 0。**不等于不存在模型抖动或相似重复动作。**
- 最终 23 段配音，85 条字幕；正文/字幕内容保留，字幕最短约 0.92 秒，未发现重叠或 Markdown 残留。
- 配音分段重新拼接与主音轨一致；章节音频拼回主音轨一致，最后仅补 130 个 24 kHz 静音样本（约 5.4 ms）。
- 实际产生 7 次拒绝，其中 2 次属于后来修复的纯繁简体误拒绝；不能把 7 次都算作确认的读错。最后的繁简体兼容修正对全部已接受段离线回放通过，没有因这项修正再次重算同一音频。
- 完整 Whisper medium 转写复核，加独立短片段核对歧义：未再发现先前的异常长配音和明确局部词组读偏。ASR 也会出现同音字、边界重复和尾词误识别，不能将转写差异直接等同于实际朗读错误。
- SyncNet 25 个有效窗口估计偏移 1–2 帧（40–80 ms），最低置信度约 4.50；通过本项目辅助阈值。官方示例校准与整片画面/两个章节接缝抽检已完成。**这些分数不是人工听辨、音素级同步或自然度认证。**
- 22 项后端/发布回归与 18 项音频质量回归通过；音频测试在独立 TTS 环境执行，后端环境中的跳过不计入通过数。前端 lint/build、源码差异检查通过，npm audit 为 0 个已知漏洞；不代表整套外部模型环境的安全审计。

原异常成片约 551.7 秒，本次约 249 秒。时长缩短主要是去除了异常生成，不是删减文案或强行倍速；本轮包含额外诊断，不作为渲染性能提升基准。

## 升级注意

**这不是仅更新前端就能生效的版本。** 需配置离线 Whisper、在独立 TTS 环境追加 `pipeline/requirements-quality.txt`，并检查升级累计 MuseTalk 补丁。旧补丁不能直接叠加新版，先备份和检查已有修改。详见 [质量检查与升级配置](QUALITY.md)。

本地默认使用较小的中文 Whisper 模型逐段检查；medium 在本次用于额外诊断，不被打包或强制设为默认。较严格的检查可能增加生成时间或误拒绝。参考视频仍会循环，声调、方言、混读、面部自然度和偶发发音细节仍需预览验收。

公开源码不含私人媒体、文案、数据库、日志、配置、模型、虚拟环境或旧品牌。不会修改用户现有素材目录，也没有部署公网服务。
